# 正式合同文档

## 内容来源

以用户当前事实与要求决定内容和格式；采用明确指定的模板时保持其结构，未指定时使用清晰一致的条款层级。历史合同可以影响结构与措辞，但不能自动带入旧项目的主体、金额、日期、比例、账户等交易数据。

未知的事实字段用 `【待填写】`；需要当事人协商决定的事项用 `【待双方确认】`。不为填满模板而编造条款或事实。

## 文件处理

- 优先使用当前 Harness 已有的本地文件、DOCX/PDF 生成和转换能力；旧 `.doc` 可复用本机 Word/Office 或兼容工具生成工作副本。
- 若已能可靠读取正文，不为统一格式额外转换；不能可靠处理时请求用户提供当前 Harness 支持的文件格式。
- 修改默认保留原文件，生成新版本；保持用户未要求更改的内容稳定。不调用 ContractBot/OpenContracts 服务器转换 DOC、DOCX 或 PDF。

## 正式输出

合同应具有清晰的标题、稳定的条款编号、必要的双方信息与签署区；数量、价格、付款节点等二维数据适合时使用表格；附件按顺序置于正文之后。长短与排版依实际合同和用户要求调整。

交付前检查：实际文件是否存在并能打开/编辑、交易关键事实未被编造或误继承、修改范围符合用户要求、必要的签署或附件结构没有遗漏。无法验证的部分应明示，不将生成动作等同于已验证成品。
