# 合同会话控制

- `结束` 是当前合同流程中的最高优先级指令：清除相关 pending / task 状态、允许新任务，并登记正在运行任务以抑制迟到结果；不物理删除已接收的暂存文件。
- `取消` 在等待操作、重复确认或阻断恢复状态下结束当前任务状态；不物理删除暂存文件。
- 等待重复确认时只接受“重新上传”“取消”“结束”。
- 等待 `BLOCKED` 恢复时，pending 只保留该未完成任务继续执行所需的文件引用和业务状态，不建立持久化 current-file 指针：
  - 缺日期或标题时接受客户直接补充；
  - 系统阻断修复后接受“继续”；
  - 接收补充后复用原 `staged_path` 发起新轮次；
  - 不要求客户重新发送文件。
- 等待操作时接受 1、2、直接合同问题、取消和结束。
- 流程中存在未完成 pending 时收到另一份文件，必须直接交给 Router intake / dedup 状态机处理；不得为了让新文件成为所谓“当前文件”而先清除旧 pending，也不得创建嵌套任务。若状态机拒绝本次输入或要求先结束，应给出可见提示。
- 无效输入必须产生可见提示，禁止静默吞掉后长期占用流程。
- 等待客户输入期间不得持有运行锁；运行标记、网络请求和 pending 业务状态分别管理。
- `awaiting_blocked_resolution` 不受普通 pending TTL 清理；只有客户明确结束/取消或流程达到后续结束状态才清理相关任务状态。
- 普通 pending TTL、结束、取消和重复/拒绝处理只影响业务任务状态，不承担 staged 文件的物理删除；文件空间回收由独立维护生命周期处理。
- 运行任务超时后必须恢复到可继续的业务状态；仍被 pending 引用的 `staged_path` 必须继续可用，且不得因业务流程结束或超时而物理删除暂存文件。
- 不提供用户侧“删除当前文件”命令，也不主动提示用户通过删除暂存文件释放空间。
