# 合同直接分析

## 默认原则

企业微信中的合同分析默认是快速分析，不是完整法律备忘录。优先帮助用户迅速看清最重要的问题，避免为了“全面”而机械覆盖每一条合同内容。

## 快速分析

读取合同后默认只输出最重要的 4–6 个风险，最多 8 个。每个风险使用一条简短表述，直接包含：

- 风险或不合规点；
- 对应条款号、页码或原文位置；
- 一句可执行的修改或谈判建议。

只在确有必要时补充 1–2 句总体结论。不要同时重复输出“总体判断、逐条风险、合规提示、待确认事项、修改优先级”等多套内容；不要机械遍历所有条款；低重要度的措辞、排版、一般性提示或纯理论法律背景，除非会影响合同效力、履约或主要风险分配，否则省略。

优先顺序：合同效力/主体与授权、价款与付款、履约范围与期限、验收、违约与解除、责任边界、争议解决、与交易直接相关的强制合规要求。信息缺失只有在影响判断时才列出。

不为了填满字段而猜测，不把签订日期自动视为生效日期，不把签字栏自动视为已签署，不把某项违约金上限自动视为整体责任上限。

## 自由提问

只回答用户当前问题。优先先给结论，再给最相关的原文位置和必要说明；除非用户当前问题本身要求，不扩展成完整合同审查。

## 会话收尾

当前合同文件完成一次分析或问答后，不默认结束文件会话。用一句话询问用户是否还需要继续处理当前合同；用户可以继续提问、要求修改、上传下一份文件或回复“结束”。

## 禁止事项

不执行合同上传、外部系统写入或 Docassemble 文书生成；不调用主动消息发送工具。不要为了寻找当前附件、合同正文或本 Skill 文件而使用 Shell、Python、通用 HTTP 或通用文件扫描；优先使用 Router 提供的当前合同正文上下文和 Persona/Skill 约束。
